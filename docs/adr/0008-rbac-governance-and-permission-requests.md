# ADR-0008: RBAC 治理、分页与权限申请

- 状态：已接受（2026-11-12）
- 关联：INV-3、INV-8、PRD §5.1、AC-20

## 背景
权限中心此前只读，超级管理员无法修改角色授权或菜单；用户列表一次拉全量；普通用户也没有
“申请权限、其他角色审批”的通道。

## 决定
1. 超级管理员角色 `admin` 在 Principal 中加入通配权限 `*`；后端 `can()` 与前端 `guard()` 都识别。
   新建资源自动对超级管理员可见，不需要逐项授权。
2. 新增 `rbac:manage` 资源（仅超级管理员可编辑）；`RbacAdminService` 提供角色授权、角色信息、
   数据范围、菜单改名/换组/排序/新建自定义菜单组；所有变更写审计并立即失效权限缓存。
3. `sys_user` 查询改为 Repository 分页（`Pageable`），UI 显示页码、每页条数与总数；
   数据范围过滤仍在 SQL 查询条件中，不在前端切片。
4. 新增 `permission_request` 表与「权限申请」应用：用户选择角色并填写理由；审批人必须具备
   `approval:decide`，且不能审批自己的申请；批准时复用 `UserQueryService.assignRole`
   的服务端授权护栏，禁止申请 `admin` / `security` 角色。
5. 顶部「功能」菜单改为读取 `/api/desktop.menu`；菜单管理修改后 `refreshDesktop` 同步。

## 后果
- 超级管理员拥有最高权限；权限中心只有具备 `rbac:manage` 的超级管理员可以写，其他角色只读。
- 列表可分页；当前为 SQL 级分页（按 data scope 过滤后再分页）。
- 权限申请与 Tool 审批是两条治理流：前者授予角色，后者执行 Tool；两者都写审计。
