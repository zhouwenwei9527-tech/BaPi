# ADR-0010：权限内操作自助确认，双人复核只用于提权

- 状态：已采纳
- 日期：2026-11-13

## 背景

早期实现把所有 `WRITE` / `DESTRUCTIVE` Tool 都映射为 `ASK` 审批，即使发起人已经拥有
`user:update`、`user:delete` 等权限，也必须退出账号、找另一位成员批准。审批人经常就是
发起人的上级或同事，导致：

- 管理员修改一个显示名称、停用或删除一个用户都无法自助完成；
- Agent 几乎每次写操作都停在“待审批”，对话被打断；
- 审批队列堆积，真正需要双人复核的提权操作反而被淹没。

## 决策

1. 新增 `ApprovalPolicy.SELF_CONFIRM`：
   - 发起人必须已经通过 RBAC 权限校验；
   - 可操作度 ≥ 60 的写入直接执行；
   - 可操作度 < 60 或 `DESTRUCTIVE` 的操作返回 `CONFIRMATION_REQUIRED`，由本人在
     风险卡片上勾选确认后，以 `confirm=true` 重新调用，直接执行；
   - 不创建审批单，不要求第二个人。
2. `ApprovalPolicy.ASK` 保留为双人复核，仅用于角色变更等可能造成权限提升的操作
   （当前为 `user.assignRole`）。
3. 权限申请流程不变：普通用户申请角色，由其他角色审批。
4. Agent 与用户管理共用同一策略：高风险操作在对话内显示确认卡，确认后直接执行；
   角色变更仍生成审批。
5. 所有路径继续执行原有的权限、数据范围、参数指纹、执行前审计与哈希链校验。

## 结果

- 有权限的成员和 Agent 不再被常规写操作打断；
- 删除、停用等低可操作度动作仍有一次明确的风险确认；
- 角色提升仍需独立复核，职责分离边界保留；
- `ToolInvocationGateway` 的单一执行入口与审计链路不变。
